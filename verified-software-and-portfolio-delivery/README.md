# Verified Software and Portfolio Delivery

## What this skill does

This skill moves technical work from a bounded idea to a tested, documented, reviewable, and appropriately published artifact.

## Why it is valuable

A GitHub repository is more convincing when it shows judgment: a clear problem, focused implementation, tests, limitations, security checks, and honest verification. This workflow prevents a portfolio from becoming a collection of unfinished or copied examples.

It helps developers:

- define a useful artifact before building;
- keep changes focused and reviewable;
- match testing to the actual risk;
- explain what works and what remains unverified;
- remove secrets, private data, and generated noise;
- confirm that the remote repository contains what was intended.

## Typical result

A public artifact has a clear README, reproducible prerequisites, verification evidence, known limitations, appropriate licensing, and a clean remote history.
