# Second-Brain Knowledge Organization

## Compatibility

This is a tool-agnostic Markdown workflow with concrete examples for Obsidian, Markdown repositories, and skill-based AI agents such as Hermes. It can also be adapted to other note systems.

## What this skill does

It helps a person design and maintain a second brain that moves from source material to evidence, durable understanding, questions, projects, and useful outputs.

It covers:

- lifecycle-based folder organization;
- source, topic, question, project, and output note types;
- title-first naming with date handling;
- search-before-create discipline;
- safe renaming and restructuring without broken links;
- the boundary between reusable agent skills, private memory, and personal vault data.

## Why it is valuable

A large note collection is not automatically useful. This workflow keeps raw captures separate from synthesis, preserves provenance, makes relationships visible, and turns knowledge into decisions or experiments. It also gives AI agents clear rules for working in a vault without exposing personal paths or treating private state as public instructions.

## Typical result

A healthy system gives each new capture an obvious temporary home, makes existing knowledge findable before duplication, keeps active work visible, and leaves a verifiable trail when notes or folders are moved.

## Included boundaries

The public skill does not contain a personal vault path, private dashboards, personal memory, credentials, session history, or account-specific configuration. Those belong in local configuration or private memory, not in a public repository.

See [`SKILL.md`](SKILL.md) for the complete workflow, naming rules, restructuring safeguards, and AI-agent boundary.
